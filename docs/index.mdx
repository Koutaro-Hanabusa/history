# 英 洸太朗（Hanabusa Koutaro）

最終更新: 2026 年 5 月 20 日

## 職務要約

幼保関連業界向けに React / TypeScript を軸とした Web 開発に従事。業務システムの改善、社外向けツールの Web 化、全社共通デザインシステムの構築に携わる。

フロントエンドを主軸に、Laravel / Go によるバックエンドも含めて担当。機能実装にとどまらず開発基盤の刷新や技術選定にも自ら踏み込み、業務効率化とエンドユーザー体験の向上、および開発プロセスの標準化に貢献。

## 職務経歴

### 2025 年 4 月〜現在 千株式会社

フロントエンドエンジニアとして、幼保関連業界向けの業務システム・管理画面・カメラマン向けツールの開発に従事。

## 得意な分野・知識・技術

- フロントエンド開発（React, TypeScript）
- デザインシステムの構築と運用

## 開発経歴

### 2025 年 5 月〜2025 年 10 月 社内向け・先生向け管理画面の改善

- メンバー / プロジェクト規模: 5〜10 人
- PHP / Go / TypeScript / Laravel / React
- 要件定義、仕様設計、コーディング、レビューを担当

#### 管理画面の改善

- 社内オペレーション向け・先生向けの 2 系統の管理画面（React + Laravel / React + Go）を改善
- 途中参加後、既存ドキュメントの読解と PdM・先行メンバーへのヒアリングを通じて、解決すべき課題を再定義
- フロントエンドを主軸に、FE / BE が連動する改修を担当

#### 申し込みフローの改善

- 申し込みフローの画面をリプレイスし、社内オペレーションの工数と顧客側の入力ミスを削減
- 編集機能を追加し、申し込みのやり直しにかかるコストを解消

#### デザインシステム

- β 版デザインシステムを構築し、後の全社デザインシステムの土台へ

### 2025 年 10 月〜2026 年 2 月 業務ツールの Web 化プロジェクト

- メンバー / プロジェクト規模: 5〜10 人
- PHP / TypeScript / Laravel / React
- 要件定義、仕様設計、コーディング、レビュー、テスト・QA を担当

#### 写真検査・納品ツールの Web 化

- カメラマンが大量の写真を検査・納品するデスクトップツールの Web 化プロジェクトに、フロントエンドエンジニアとして参画
- フロントエンドの体制が限られるなか、機能実装と並行して開発基盤・品質基準の整備を推進

#### 開発基盤・品質改善

- 機能実装に先立ち、ライブラリ更新・テスト・Lint 環境を整備し、技術的負債を解消
  - [プロダクトブログ](https://productblog.sencorp.co.jp/entry/2025/12/15/100000)
- Lint 導入で顕在化した `autofocus` 属性を含むアクセシビリティ上の問題を解消
  - [autofocus 属性のアクセシビリティを扱った発表スライド](https://slide.burio16.com/autofocus-correct-usage)（社内 LT 会 / Frontend Conference Nagoya 2026 前夜祭）
- 既存 UI ライブラリから Tailwind CSS への部分移行を提案・実施し、段階的な移行方針を策定

#### 写真バリデーションの再設計

- 写真バリデーションの Zod によるスキーマベース化を、技術検証から実装まで担当
- 業務ドメイン固有の例外パターンに対応しつつ、既存仕様を変えずに型安全性・保守性を改善
- バリデーションの所要時間(2500枚想定)を 489,173ms から 4,134ms へ短縮し、納品フロー全体の高速化に寄与

#### 段階的リリース

- 社内向けの先行公開期間を設け、フィードバックを取り込みながら段階的にリリースする計画を設計

2026 年 3 月からは、全社的なリプレイス計画のフロントエンドチームに参画。進行中のため詳細は割愛するが、取り組みの概要は自己 PR に記載。

## 自己 PR

### フロントエンドを軸にした開発と新しい技術へのチャレンジ

React / TypeScript を主軸に、社内向けの業務システムから顧客向けの管理画面、社外スタッフ向けのツールまで、ユーザーが直接触れるプロダクトの設計・実装を担当してきました。必要に応じて Laravel / Go によるバックエンド改修にも踏み込み、API 設計や FE/BE 連携も対応できる点が強みです。

#### 新しい技術の検証・導入

- フロントエンドのみで 1 プロダクトを構築する PoC で技術選定を担当し、TanStack Router / TanStack Start の導入を決定
- 事例が少ない技術でも、ディレクトリ構成・ルーティングの責務・運用方法を技術検証し、長期運用を見据えたアーキテクチャへ落とし込み
  - [TanStack Router / Start の技術選定とディレクトリ構成に関する発表スライド](https://slide.burio16.com/tanstack-router-dir-structure)

### デザインシステムの構築と展開

管理画面の改善プロジェクトで構築した β 版デザインシステムが、全社デザインシステムの土台として採用されました。現在は全社共通デザインシステムの新規構築にフロントエンドとして参加しています。作ることだけでなく、利用者が正しく継続的に使える状態をつくることを重視しています。

#### コンポーネント・品質基盤

- コンポーネントの設計・実装に加え、カタログ、VRT、CI/CD、Figma Code Connect を整備し、複数プロダクトで安心して変更・利用できる品質基盤を構築
- VRT は、ベースライン画像を Git 管理せず、main ブランチのコードから再生成可能な CI キャッシュとして扱う運用を設計。PR 上で Before / After / Diff を確認し、意図した変更だけを更新できるレビュー体験を整備
- Figma 仕様と実装・カタログ・Code Connect の同期を行い、デザインと実装の乖離を防ぐ運用を推進
- デザインシステム固有の Lint ルールを実装し、利用ルールから外れるコードを開発時・CI で検出できる状態を整備

#### 開発基盤・アーキテクチャ

- Vite+ を中心に、lint / format / test / タスク実行 / Git hooks を統合。タスク間の依存関係とキャッシュを明示し、継続的に開発・配布できるツールチェーンへ刷新
  - [Vite+ 導入とツールチェーン統合に関する発表スライド](https://slide.burio16.com/vite-plus-retro)（Vue Fes Japan 2026 登壇予定）

#### AI 駆動開発への展開

- デザインシステムの MCP サーバーと Skills を実装し、AI エージェントが最新のコンポーネント仕様・利用ルールを参照して正しく実装できる環境を整備
- Nix の devShell と direnv で開発環境を再現可能にし、環境構築の障壁を低減。デザイナーが Figma Dev Mode MCP・AI エージェント・社内デザインシステムを組み合わせて React のプロトタイプを構築できる環境を整備
  - [Frontend Conference Kansai 2026 採択 LT「AI時代に、みんなでフロントを作るためのNix」](https://fortee.jp/fec-kansai-2026/proposal/03c1cdcf-5644-420d-bf67-5037bd6af6a5)

### ユーザー体験向上への貢献

管理画面の改善やツールの Web 化では、単なる機能実装にとどまらず、エンドユーザーの使いやすさを重視した開発を行いました。その結果、社内オペレーションの効率化だけでなく、顧客や現場スタッフからも好評を得られています。

### 継続的なアウトプット

- 社内 LT・外部イベントで計 9 回の登壇（個人開発、OSS へのコントリビュート、業務で遭遇した実装上の落とし穴 など）
- 大規模カンファレンスの参加レポート執筆（例: [フロントエンドカンファレンス東京 2025 参加レポート](https://productblog.sencorp.co.jp/entry/2025/09/29/140056)）
- 社内 LT 会のオーガナイザを継承し、学びの場づくりを継続
